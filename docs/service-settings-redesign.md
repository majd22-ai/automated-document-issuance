# تنظيم إعداد الخدمة

التعديل يخص وضوح شاشة الإدارة، مع الحفاظ على أسماء الحقول والتحقق والخدمات والجداول الحالية.

- معلومات الخدمة في بطاقة أولى واضحة، مع إبقاء رمز ونوع الخدمة ثابتين عند التعديل.
- شروط الخدمة والمستندات في بطاقة مستقلة؛ بيانات المواطن المطلوبة تُختار بمربعات عربية بدل كتابة مفاتيح تقنية.
- الرسوم والعملة والمدة في بطاقة مختصرة، والفراغ يعني أن البيانات لم تعتمد.
- الاعتماد والنشر في بطاقة أخيرة مع مصدر الاعتماد ورسائل الأخطاء بجانب الحقول.
- إعدادات الأهلية والتجديد والحقول المنظمة والمرفقات والمواعيد والإصدار والتكاملات في قسم متقدم مطوي؛ يحتفظ بكل القيم ولا يغير قواعد الطلبات بمجرد فتحه أو طيه. يظهر القسم المرتبط بخطأ الخادم تلقائيًا، ويفتح JavaScript الأقسام المطوية عند خطأ التحقق في المتصفح.
- تقييم أهلية المواطن انتقل إلى صفحة مستقلة محمية بنفس صلاحية الإدارة، مع استخدام نموذج الحفظ والمسار الحاليين.
- تظل شروط التفعيل والاعتماد والمرجع وقواعد الإصدار والتكاملات كما في Form Request الحالي. لا تُفرض رسوم أو مدد أو متطلبات جديدة.

## الملفات

`resources/views/admin/services/edit.blade.php`، `technical.blade.php`، `index.blade.php`، `assessment.blade.php`، `assessment-form.blade.php`، `public/css/service-settings.css`، `public/js/service-settings.js`، `AdminGovernmentServiceController.php`، `routes/web.php`.

## التحقق

نجحت اختبارات إدارة الخدمات: 14 اختبارًا و124 تحققًا، منها إرسال قيم النموذج الجديد والتحقق من بقاء قواعد الحقول والمرفقات والمواعيد والتكاملات والإصدار دون تغيير، وصلاحية الوصول لصفحة التقييم، وفتح القسم المتقدم وإبقاء إدخال المستخدم عند الخطأ. نجح كذلك اختبار JavaScript لفتح الأقسام المحتوية على حقل غير صالح. قبل إضافة هذه الاختبارات نجحت مجموعة الخدمات والإصدار (40 اختبارًا و333 تحققًا). نجح تجميع Blade وفحص صياغة JavaScript وPHP. لم تتوفر جلسة متصفح للاختبار البصري الفعلي.

```powershell
php vendor/phpunit/phpunit/phpunit --filter=GovernmentServicesTest --do-not-cache-result
node --test tests/frontend/service-settings.test.cjs
php artisan view:cache
php artisan view:clear
```
