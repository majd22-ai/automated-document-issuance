# المتطلب السادس: الصور والمرفقات

## ما نُفذ

تم فحص Laravel 12.65.0 وPHP 8.2.12 والمصادقة والصلاحيات والخدمات والطلبات والتحقق السابق. لم يكن هناك جدول أو مكتبة مرفقات؛ أضيف جدول واحد `citizen_attachments` وعلاقات Eloquent مع المواطن والخدمة والطلب والموظف المراجع. لا يتغير نظام المصادقة أو حالات الطلب أو آلية إصداره.

من صفحة الخدمة أو بدء الطلب يستطيع المواطن فتح «استكمال الصور والمرفقات». تظهر الحقول من `verification_rules.documents` الخاصة بالخدمة؛ المستندات الموجودة في `required_documents` إلزامية. للمرفق الاختياري عرّف قاعدته مع `optional:true` ولا تضع اسمه ضمن القائمة الإلزامية. قواعد المستندات غير المعتمدة لا تُخمن ولا تُقبل تلقائيًا.

يُحفظ ملف واحد لكل مواطن/خدمة/نوع مستند/سياق، بقيد فريد في قاعدة البيانات. الملفات قبل التقديم تبقى مرتبطة بالمواطن والخدمة، وتُربط بالطلب داخل معاملة تقديمه النهائية. المرفق المرتبط بطلب سابق لا يُستخدم تلقائيًا لطلب جديد.

## التحقق والتخزين

- يتحقق الخادم من نجاح الرفع، والقراءة، والحجم الفعلي، وMIME باستخدام fileinfo، ومطابقته لامتداد مسموح وقواعد نوع المستند.
- صور PNG وJPEG تُفحص أبعادها وتُفك باستخدام GD. حد المعالجة الافتراضي 20 مليون بكسل.
- الحد الافتراضي للصور الشخصية 2048 كيلوبايت وللمستندات 5120 كيلوبايت، قابلان للضبط عبر `ATTACHMENT_PHOTO_MAX_KB` و`ATTACHMENT_DOCUMENT_MAX_KB` في البيئة. حدود PHP وخادم الويب تظل سارية وقد تكون أقل.
- PDF يتطلب مسارًا مطلقًا لمحلل `pdfinfo` موثوق في `ATTACHMENT_PDFINFO_BINARY`. يُشغّل دون shell بمهلة ثماني ثوانٍ، ويُشترط نجاح التحليل وعدد صفحات صالح وعدم وجود أخطاء. لا يوجد محلل مثبت اكتشفه الفحص؛ لذلك PDF مرفوض حاليًا برسالة واضحة. لم تُضف مكتبات جديدة أو تثبت أدوات تلقائيًا.
- التخزين على قرص مستقل `attachments` في `storage/app/citizen-attachments`، خارج public وقرص التخزين القابل للمشاركة. `serve=false` ولا توجد روابط عامة أو storage:link.
- مسارات UUID وامتداد يحدده الخادم، مع SHA-256 وحجم محفوظين والتحقق من تطابق البيانات قبل العرض وعند فحص الأهلية. الاسم الظاهر منفصل ومحدود ومهذب، ولا يستخدم كمسار أو اسم داخلي.
- لا يُسمح للمتصفح بتحديد الملكية أو مسار التخزين أو بيانات الاعتماد والمراجعة. لا يعاد المسار أو checksum في تسلسل النموذج العام.

## المعاينة والمراجعة والتعديل

كل طلب معاينة أو تنزيل يمر بالمصادقة وPolicy. المواطن يرى ملفاته فقط؛ الموظف المخول بالاطلاع على بيانات المواطن يستطيع معاينة المرفقات ومراجعتها. دور المدير وحده لا يمنحه الاطلاع على الوثائق. الاستجابات `no-store, private` مع `nosniff` وCSP، ويُنزل PDF بدل تشغيله داخل أصل المنصة.

الحالات: مرفوع (فحص فني فقط)، بانتظار المراجعة، مقبول للمرفق، مرفوض، يحتاج إلى استبدال. لا يعتمد المواطن مرفقه. الموظف يسجل قرار المرفق فقط وسببًا عامًا يظهر للمواطن وتاريخ انتهاء موثقًا عند الحاجة. رمز نسخة يتغير عند الرفع أو المراجعة يمنع اعتماد نسخة استُبدلت بعد فتح الصفحة. لا تمنح هذه الوحدة صلاحية اعتماد الطلب أو إصدار الوثيقة.

الاستبدال متاح قبل التقديم، أو لطلب حالته `requires_correction` فقط. التعديل ممنوع بعد القبول أو الاعتماد أو الإغلاق، وأثناء المعالجة والمراجعة العادية. يجب أن ينجح فحص الملف الجديد وتخزينه وحفظه قبل حذف القديم بعد commit. فشل الرفع أو الكتابة لا يحذف القديم، وفشل التسجيل بعد commit لا يمحو الملف الجديد. حذف الإلزامي مرفوض؛ الاختياري يمكن حذفه ضمن السياق القابل للتعديل نفسه.

تُسجل عمليات الرفع والاستبدال والحذف ومراجعة المرفق بمعرفات داخلية وحالة فقط؛ لا تسجل الملفات أو أسماؤها أو محتوياتها أو أسبابها. ينبغي مراقبة صحة وجهة Logs؛ ففشل التسجيل لا يؤدي إلى حذف ملف محفوظ. فشل تنظيف التخزين يسجل `attachment_cleanup_required` إن كانت وجهة السجل متاحة.

## التكامل مع المتطلب الخامس

`LocalAttachmentEvidenceSource` يحقق عقد الأدلة الموجود ويعيد نتائج حقيقية من الملفات الخاصة. تبقى مصادر الفحص الطبي والأصالة والموانع الخارجية غير متاحة حتى تكاملها، ولا تُصطنع لها نتائج.

المرفق الناقص يمنع اجتياز الشرط الإلزامي. المرفق المرفوع الذي يحتاج مراجعة لا يجتازه. الرفض الصريح يمنع اجتيازه حتى لو لم تشترط الخدمة المراجعة ابتداءً. تغير قواعد الخدمة، أو فقدان الملف، أو عدم تطابق محتواه، يعيد حالة تعذر التحقق. تغيير المرفق يبطل الملخص السابق؛ يعاد فحص الأهلية فعليًا عند التقديم النهائي تحت أقفال المواطن ثم الخدمة. التعديل المرتبط بطلب يمسح نتيجة الفحص القديمة حتى يعاد فحصه.

## التشغيل والتحقق

```powershell
php artisan migrate --force
php vendor/bin/phpunit --do-not-cache-result
php vendor/bin/phpunit tests/Feature/CitizenAttachmentsTest.php --do-not-cache-result
php artisan view:cache
node --test tests/frontend/portal-demo.test.cjs
```

لا تستخدم migrate:fresh. شُغلت الاختبارات على SQLite بالذاكرة وقاعدة MySQL المعزولة التي ينتهي اسمها بـ `_testing`. تستخدم اختبارات المرفقات Storage::fake وتحقق الصلاحيات ومسارات HTTP، ولا تزرع ملفات مواطنين حقيقيين. تُضاف النتائج النهائية الفعلية أدناه.

## ما يحتاج إعدادًا خارجيًا

محلل PDF عند الرغبة في قبوله، وضبط حدود PHP/خادم الويب، ومكافحة البرمجيات الخبيثة إن تطلب التشغيل الفعلي ذلك. لم يُنفذ فحص مضاد للبرمجيات الخبيثة ولا يُدّعى وجوده. يلزم إعداد النسخ الاحتياطي والتشفير على مستوى وسيط التخزين وسياسة الاحتفاظ بالمستندات وتنظيف الملفات اليتيمة بعد أعطال النظام. لا تحذف هذه الوحدة ملفات مواطنين قديمة تلقائيًا.

القواعد القانونية واعتماد المستندات تظل مسؤولية الجهة المختصة. لم تُفعّل خدمات غير معتمدة ولم يُعتمد طلب حقيقي بغرض الاختبار. لم تُختبر الواجهات بصريًا عبر المتصفح؛ جرى اختبار HTTP وتجميع Blade.
