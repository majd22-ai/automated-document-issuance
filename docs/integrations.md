# التكامل والتحقق الإلكتروني — المتطلب 11

## التنفيذ وحدوده

المشروع Laravel 12.65.0 وPHP 8.2.12، وقاعدة التشغيل MySQL/MariaDB. أُعيد استخدام طلبات الخدمات والوثائق والفحوصات والإيصالات والصلاحيات والأهلية والمراجعة والإصدار الموجودة. لم تُضف مكتبات أو منظومة مصادقة بديلة.

لا يوجد مزود حكومي خارجي مهيأ: `config/integrations.php` يحتوي قائمة مزودين فارغة. لا يمكن اعتبار إيصال محلي أو فحص داخلي تحققًا رسميًا. لا تنشئ هذه الطبقة دفعات، ولا تغيّر حالة السداد، ولا تصدر ختمًا رسميًا. الاستعلام الخارجي الحقيقي يتطلب عقد الجهة وبيانات اتصال معتمدة. لم تُنشأ عناوين API أو Webhooks تخمينية.

## البنية والبيانات

- `IntegrationProvider` عقد موحد لمحول كل جهة؛ `VerificationContext` يبني الحد الأدنى من بيانات الخادم، و`VerificationResult` يعيد نتيجة موحدة.
- `IntegrationTransport` يفرض HTTPS والمنفذ 443 ومضيفًا محددًا ومسارات مصرحًا بها، ويمنع إعادة التوجيه وعناوين IP وlocalhost وبيانات الاعتماد داخل URL. تحقق TLS مفعّل.
- `IntegrationManager` يحجز المحاولة داخل معاملة قصيرة، وينفذ الاتصال خارج أقفال قاعدة البيانات، ثم يعيد التحقق من الصلاحية والبيانات والسياسة قبل حفظ النتيجة.
- `IntegrationRequirements` يربط المتطلبات الإلزامية بالأهلية والاعتماد والإصدار. النتيجة منتهية الصلاحية أو غير الموثوقة لا تسمح بالمرور. الخدمات التي ليس لها قواعد تكامل تحتفظ بسلوكها.
- الترحيل `2026_10_31_000001_add_electronic_integrations.php` يضيف `integration_rules` لجدول الخدمات، و`can_verify` للصلاحيات، وجدول `integration_attempts` المرتبط بالطلب والمواطن والموظف والوثيقة المستهدفة. لا يُعاد إنشاء الجداول الموجودة. الرجوع عن الترحيل لا يحذف سجل التدقيق.

تُحفظ الحالة والمزود والتوقيت والانتهاء وعدد المحاولات والمدة ورمز HTTP ورمز خطأ ثابت. لا تُحفظ أجسام الاستجابة أو كلمات المرور أو الرموز السرية أو البيانات الطبية في سجل المحاولات. بصمات HMAC مخفية وتكشف تغيّر المدخلات والسياسة وإعدادات المزود دون تخزين المدخلات نفسها.

## أنواع التحقق

| النوع | البيانات المرسلة عند توفرها | الأثر |
|---|---|---|
| identity | الرقم الوطني ومرجع الطلب | تحقق هوية؛ لا يُقبل الاسم وحده |
| document | وثيقة مختارة يملكها المواطن، رقمها ونوعها وتواريخها | دليل أصالة للوثيقة نفسها فقط؛ لا تُرسل صور المرفقات |
| medical | الرقم الوطني ومرجع الفحص وتاريخه | تحقق المصدر؛ لا تُرسل التشخيصات أو الملاحظات الخاصة ولا تُستبدل نتيجة الفحص المحلية |
| payment | مرجع إيصال موجود والمبلغ والعملة المتطابقان مع الرسم | استعلام فقط؛ لا يُنشأ إيصال أو دفع ولا تتغير حالة السداد |

غياب البيانات ينتج حالة واضحة `unknown` دون اتصال. الحالات الأخرى: غير مطلوب، غير مهيأ، قيد الانتظار، قيد التنفيذ، متحقق، مرفوض، غير مطابق، غير متاح، فشل، ومنتهي الصلاحية.

## السياسات والصلاحيات والواجهات

يحرر المدير قواعد `integration_rules` من صفحة الخدمة الحالية. الأنواع محددة، ولكل قاعدة `required` و`provider` و`max_age_minutes` بين 1 و10080. تُحفظ القواعد في لقطة الطلب وتدخل في إصدار قواعد الخدمة. لا يسقط شرط إلزامي سابق عند حذفه من القاعدة الحالية؛ تغيّر المزود المتعارض يمنع الاعتماد حتى تُحل السياسة إداريًا. تؤخذ مدة الصلاحية الأكثر تشددًا.

المواطن يقرأ طلبه ونتائجه فقط. الموظف يحتاج منحة `can_verify` صريحة للخدمة؛ لا تكفي صلاحية المراجعة. المدير يدير المنح والسياسات ويقرأ إعدادات المزود الآمنة، دون تحرير الأسرار أو URLs من المتصفح. جميع صفحات النتائج والتاريخ محمية وتستخدم Pagination و`no-store`.

المسارات الجديدة:

- `GET /citizen/applications/{id}/verifications`
- `GET /employee/verifications`
- `GET /employee/applications/{id}/verifications`
- `POST /employee/applications/{id}/verifications`، محدود إلى 10 طلبات في الدقيقة.
- `GET /admin/integrations`

الواجهة عربية RTL، وتعرض المصدر والحالة والصلاحية والتاريخ دون أسرار. عُدلت صفحات تفاصيل الطلب والخدمة والمنح وروابط اللوحات لدمجها. يجب التمييز بين النتيجة التاريخية المحفوظة وصلاحية التحقق الحالية.

## منع التكرار ومعالجة الأخطاء

إعادة UUID نفسه للطلب والنوع والوثيقة تعيد المحاولة المحفوظة دون اتصال. محاولة مختلفة أثناء التنفيذ تعيد 409. يوجد قيد فريد لحجز الطلب/النوع، وتُحرر المحاولة المتوقفة بعد دقيقتين كحالة غير مؤكدة عند محاولة لاحقة؛ لا تُعاد آليًا. النتيجة الخارجية قيد الانتظار تُحفظ، والاستعلام اللاحق يحتاج قرارًا صريحًا ومفتاحًا جديدًا.

المهلة الافتراضية 8 ثوان والاتصال 3 ثوان، وحدهما الأعلى 15 و5 ثوان. الافتراضي دون إعادة محاولة؛ الحد الأقصى إعادتان فقط لـ429 و5xx للاستعلامات المقروءة. لا تعاد مهلة الاتصال تلقائيًا. أخطاء الشبكة أو البيانات غير الصالحة لا تصبح نجاحًا. حالات التحقق الحاسمة تحتاج HTTP 2xx ومحاولة اتصال وربطًا موثوقًا بهوية صاحب الطلب ومرجع الاستعلام. أي تغير للبيانات أثناء الاتصال يبطل النتيجة.

## إضافة جهة حقيقية وتفعيلها

1. الحصول على وثائق رسمية تحدد URL والمضيف والمسارات والمصادقة ومخطط البيانات وربط الهوية والردود والمهل وحدود المعدل وحق إعادة المحاولة، وتفويض إرسال البيانات اللازمة.
2. إنشاء محول يطبق `IntegrationProvider` ويستخدم العقد الحقيقي. عليه التحقق من بنية الرد وتوقيعه عند اشتراطه وربطه الدقيق بالمواطن والوثيقة/الفحص/الإيصال ومرجع الاستعلام، قبل إرجاع `bound=true`. لا تعتمد على كلمة نجاح وحدها.
3. تسجيله في `config/integrations.php` تحت مفتاح المزود مع `adapter`, `label`, `enabled`, `approved` وإعدادات النقل `base_url`, `allowed_host`, `endpoints`. استخدم أسماء أنواع التحقق لمفاتيح المسارات. المصادقة Bearer متاحة عند تحديد `auth=bearer` و`token`؛ أي مصادقة أخرى تُنفذ حسب العقد الرسمي.
4. تحميل الأسرار من متغيرات البيئة/مخزن أسرار النشر فقط. أسماء متغيرات الجهة تُحدد عند معرفة عقدها؛ لا توجد أسرار مطلوبة حاليًا. المتغيران العامان: `INTEGRATION_TIMEOUT_SECONDS=8` و`INTEGRATION_CONNECT_TIMEOUT_SECONDS=3`.
5. اختبار المحول ببيانات مصرح بها في بيئة الجهة التجريبية، واختبار الردود السلبية والتوقيع والتطابق والتكرار، ثم اعتماد الإعداد وتفعيل قاعدة الخدمة ومنح الموظف الصلاحية.
6. تشغيل `php artisan config:clear` بعد تعديل إعدادات البيئة، ثم التحقق من صفحة الإدارة. لا يُفعّل اختبار المحاكاة في الإنتاج.

المحول `tests/Support/TestVerificationProvider.php` خاص بالاختبارات، ويستخدم `Http::fake()` وعقدًا اصطناعيًا لا يمثل جهة رسمية. يرفض المدير تشغيل محولات مساحة `Tests` خارج بيئة الاختبار. لا توجد وظيفة Webhook لغياب عقد توقيع ومنع إعادة الإرسال؛ يجب تصميمها واختبارها عند توفير العقد. المهام الحالية محدودة زمنيًا؛ لا توجد طوابير خارجية أو إعادة إرسال تلقائي مكلف.
