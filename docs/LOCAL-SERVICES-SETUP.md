# إعداد كتالوج الخدمات للتجربة المحلية

## البيئة والتحقق

تم التنفيذ على `APP_ENV=local`، Laravel 12.65.0 وPHP 8.2.12، وقاعدة MySQL `e_issuance` باتصال loopback وخادم XAMPP المحلي. لم تُطبع أسرار الاتصال. لا يوجد Database URL يتجاوز الاتصال المحلي. أظهر `migrate:status` أن جميع الترحيلات منفذة، وأعاد `php artisan migrate --no-interaction`: `Nothing to migrate`.

هذا إعداد تجربة داخلية غير رسمية، ولا يمثل اعتمادًا حكوميًا. لا تُنقل هذه الإعدادات إلى الإنتاج دون مراجعة المسؤول وتوفير المراجع والرسوم وسياسات الإصدار الرسمية.

## النتيجة الفعلية

ست خدمات فُعّلت حديثًا، وخدمتان بقيتا مفعّلتين. الصفحة العامة `/services` تعرض الثماني. لم يتغير نوع وثيقة أو رمز خدمة أو اسمها، ولم تُنشأ خدمات مكررة.

## ما حُفظ وما أُكمل

- رسوم إصدار البطاقة الموجودة `3500.00 ريال يمني` محفوظة. رسوم الخدمات السبع الأخرى بقيت `null`؛ لا تعني أنها مجانية، ولم تُسجّل رسوم افتراضية أو إيصالات سداد.
- بقي مرجع البطاقة ومدتها السابقة وإعداد شهادة الميلاد ومرجعها ومركزها التجريبي الموجود كما هي.
- المراجع الناقصة فقط أصبحت: «تجربة داخلية غير رسمية — لا يوجد اعتماد حكومي».
- أُكملت إعدادات الإصدار الفارغة فقط للعمليات التي يدعمها المحرك: إصدار وتجديد. النسخة داخلية `internal_html` وبادئة `TEST` ضمن الرقم الداخلي الذي يولده المحرك ببادئة `INT`؛ لا رقم حكومي مفترض.
- لم تُخترع مدة صلاحية أو مدة إنجاز أو مراكز استلام. إعداد التجربة لا يفرض تاريخ انتهاء حكوميًا، ويتيح مسار تسجيل عنوان التسليم الموجود في التطبيق دون إنشاء مركز، ولا يرسل طردًا فعليًا. لا يتغير بذلك أي إعداد تسليم صحيح موجود.
- لخدمات التجديد التي لا تملك سياسة حالة سابقة، حُددت حالة المحرك الداخلية `active` كتجربة فقط. لم تُخترع نافذة تجديد قانونية أو مدة صلاحية، ولا يُسمح بالتجديد دون الوثيقة المرتبطة بالمواطن وفحوص الأهلية الحالية.
- لم تُعطّل شروط أهلية المواطن أو التفعيل أو المراجعة أو السداد الموجودة. إذا كانت خدمة تشترط السداد ورسومها ناقصة، يرفض الأمر العملية كلها دون حفظ جزئي.
- **إصدار بدل الفاقد النهائي غير مدعوم حاليًا في `IssueDocuments`**؛ بقيت `issuance_rules` له فارغة. يلزم تنفيذ واعتماد سياسة استبدال مستقلة قبل تشغيل إصدار الوثيقة. ظهور الخدمة ورابطها لا يعني اكتمال هذا المحرك.
- **شهادات الميلاد الناتجة نماذج تجريبية داخلية، وليست وثائق حكومية ولا تصلح لإثبات الحقوق القانونية**. قالب PDF الحالي يتضمن هذا التنبيه، وكذلك قالب النسخة الداخلية.

## آلية Laravel المستخدمة

أُضيف الأمر المحدود `services:prepare-local`. لا يقبل إلا البيئة المحلية وقاعدة `e_issuance` الصريحة على MySQL loopback دون Database URL، أو قاعدة الاختبار SQLite داخل الذاكرة عند الاختبار فقط. يرفض الإنتاج وأي اسم قاعدة مختلف.

```powershell
# معاينة دون حفظ؛ التنفيذ الفعلي لهذه المهمة تم بالفعل
php artisan services:prepare-local --database=e_issuance
# حفظ عند الحاجة في البيئة المحلية فقط
php artisan services:prepare-local --database=e_issuance --apply
```

يتعامل مع ثمانية رموز موجودة فقط، ويتحقق من تطابق أنواعها وعملياتها. لخدمة إصدار البطاقة لأول مرة، يضيف الإعداد الافتراضي التجريبي عند غيابه، ويطابق قاعدة رفع ومراجعة مع كل مستند مطلوب. لا يستبدل قائمة شروط أو مستندات موجودة، ولا يخترع رسومًا أو مدة إنجاز أو صلاحية قانونية. يستخدم قواعد `SaveGovernmentServiceRequest` وعمليات التحقق اللاحقة نفسها لمسار الإدارة، ثم Eloquent داخل معاملة وقفل الصفوف. يحتفظ بحماية المعرفات وإصدارات القواعد وObservers وسجل التدقيق، ولا يستخدم SQL مباشرًا أو ينشئ حسابات أو يمنح صلاحيات. يُسجل الحدث `service.local_trial_prepared` كعملية CLI دون نسبتها إلى موظف لم ينفذها. التشغيل المكرر لا يحفظ تحديثًا عندما لا توجد تغييرات.

بعد الترقية، أعد تهيئة الخدمة وبيانات سجل الشهود الاصطناعية محليًا:

```powershell
php artisan services:prepare-local --database=e_issuance --apply
php artisan db:seed --class=LinkedCivilMockSeeder
```

جميع شروط ومرفقات البطاقة التي يضيفها الأمر افتراضية لمشروع التخرج فقط. قاعدة الصورة المطلوبة في الاستمارة منفصلة عن مستند «صورتان» إن ورد ضمن القائمة. رفع المرفق وحده لا يكفي عند طلب مراجعته؛ يحتاج الموظف المخوّل إلى اعتماد المرفق قبل إعادة التقديم.

لإنشاء بيانات عرض اصطناعية لمسودة واحدة فقط، استخدم رقم المسودة الظاهر في الرابط. الأمر يتطلب حساب مواطن مفعلًا من محاكاة محلية، ومصادقة تجريبية موافقًا عليها، ويبدأ بمعاينة دون حفظ:

```powershell
php artisan identity-card:prepare-demo-submission --form-id=2
php artisan identity-card:prepare-demo-submission --form-id=2 --apply
```

ينشئ التقييم والمرفقات بمرجع `DEMO` وأسماء ملفات موسومة، ويعطل مراجعة المرفق الإضافية داخل هذا السيناريو المحلي فقط. لا يرفع الطلب تلقائيًا ولا يمنح صلاحية لأي موظف؛ افتح الخطوة 7 مجددًا لتحديث ملخص الاستمارة ثم قدمها يدويًا. لا تستخدم هذا الأمر خارج قاعدة العرض المحلية.

## ما يبقى خاصًا بكل مواطن وموظف

لا ينشئ إعداد الخدمات تقييم أهلية لمواطن عشوائيًا ولا يمنح موظفًا صلاحيات عامة. للمسودة التجريبية المختارة يمكن استخدام الأمر أعلاه؛ أما التقييم الإداري اليدوي فيسجل من `/admin/services/{service}/assessment` بمرجع مشروع واضح ونتائج تحقق سيناريو العرض فقط. ثم يمنح المدير موظفًا تجريبيًا محددًا صلاحية المراجعة من `/admin/review-permissions` إذا كان سيعالج الطلب. هذه الخطوات المنفصلة تحافظ على ملكية الطلب وسجل المراجعة وتمنع اعتبار كل الحسابات مستوفية تلقائيًا.

إكمال إعداد إصدار البطاقة يرفع إصدار قواعدها تلقائيًا بحسب آلية النموذج الحالية؛ التقييمات القديمة قد تحتاج مراجعة المسؤول لإصدار القواعد الجديد. لم تُحدّث تقييمات المواطنين تلقائيًا لتجاوز ذلك.

## الصلاحيات التي يراجعها المسؤول

لم تُنشأ أو تُعدّل صلاحيات. حسب اختصاص الموظف والخدمة، راجع الصلاحيات القائمة: `can_review` للمراجعة، `can_approve` للاعتماد، `can_assign` للإسناد، `can_issue` للإصدار، `can_deliver` للتسليم، و`can_verify` للتحقق الخارجي عند الحاجة. لا يلزم منح الجميع جميع الصلاحيات. تظل صلاحيات الاطلاع على بيانات المواطن مطلوبة وفق السياسات الحالية.

- لا تغيير JavaScript أو CSS؛ لا حاجة لبناء npm لهذه المهمة. لم يُختبر إصدار وثيقة حكومية أو تسليم حقيقي، ولم يُدّع ذلك.
