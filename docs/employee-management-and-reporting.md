# المتطلب 12 — إدارة الموظفين والرقابة والتقارير

## البنية والتنفيذ

Laravel 12.65.0 وPHP 8.2.12؛ قاعدة التشغيل MySQL/MariaDB. أُعيد استخدام `users` والمصادقة بالجلسات وLaravel Password Broker وصلاحيات الخدمات `service_review_permissions` وبيانات الطلبات والقرارات والوثائق والإيصالات ومحاولات التكامل. لم تُضف حزمة أو منظومة أدوار موازية، ولم يُنفذ المتطلب 13.

المدير ينشئ حسابات الموظفين ويعدل بياناتها ويعطلها ويختار القسم والمسمى ورقم الموظف. الاسم/البريد/اسم المستخدم ورقم الموظف تخضع للتحقق والقيود الفريدة الموجودة/المضافة. الحسابات لا تُحذف من الواجهة. تمنع الإدارة تعطيل الحساب الإداري المنفذ أو سحب دوره من نفسه. صفحة الأدوار القديمة توجّه إلى إدارة المستخدمين الفعلية؛ صلاحيات المراجعة والاعتماد والإسناد والإصدار والتسليم والتحقق تبقى في صفحة المنح الحالية لكل خدمة.

الأقسام لها اسم فريد ووصف وحالة، دون فرض مدير قسم أو هيكل غير مطلوب. يمكن إضافة القسم وتعديله وتعطيله، ولا توجد واجهة حذف. التعطيل يحجب التقارير عن الموظف المفوض لقسم معطل، ولا يحذف الحسابات أو التاريخ ولا يسحب تلقائيًا صلاحيات الخدمات الأخرى.

## الصلاحيات

| الفئة | الصلاحيات |
|---|---|
| admin نشط | إدارة الموظفين والأقسام والأدوار والمنح، التقارير لجميع الأقسام، التدقيق وتصديره |
| employee نشط دون منحة تقارير | وظائف الخدمات بحسب منحها السابقة فقط |
| employee مع `report_scope=department` وقسم نشط | تقارير مجمعة للقسم الحالي فقط |
| الموظف السابق مع `can_export_reports=true` | تصدير التقارير المجمعة لقسمه؛ لا يتيح سجل التدقيق |
| citizen | لا وصول إلى إدارة الموظفين أو التقارير أو التدقيق |

المنحتان لا تقبلان التعديل من الملف الشخصي/التسجيل ولا توجدان ضمن mass assignment. منحهما للمدير فقط. لا يوجد تفويض ضمني لمدير قسم بإدارة حسابات الآخرين. تغيير معرف القسم أو الموظف في URL لا يتجاوز النطاق؛ كل تنزيل يعيد المصادقة والتفويض. لا يُشارك Cache لتقارير الأقسام.

## كلمات المرور والجلسات

كلمات المرور الجديدة للموظفين بطول 12 حرفًا على الأقل وتخزن بآلية Laravel `hashed`؛ لا تعاد أو تعرض بعد الإنشاء. إعادة التعيين تستخدم رابط Laravel Password Broker إلى بريد الموظف، برمز محدود الصلاحية ومستخدم مرة واحدة وتحديد معدل الإرسال والمحاولات. لا يرسل رابط الاستعادة إلى `log` أو `array`؛ الإعداد الحالي يحتاج بريدًا حقيقيًا حتى يعمل الإرسال. يمكن اختبار الرمز محليًا عبر الاختبارات دون إرسال حقيقي.

تغيير كلمة المرور أو الدور أو الحالة يدور `auth_version` ويلغي remember_token، وتفحص الجلسة نسختها في كل طلب. الجلسات القديمة التي سبقت إضافة النسخة تحتاج تسجيل دخول جديدًا مرة واحدة. دخول Remember Me الصالح يهيئ النسخة؛ تغيير كلمة المرور يبطل رمزه السابق. يُسجل آخر دخول بدءًا من تفعيل الوحدة، ولا يُختلق تاريخ سابق.

## التدقيق

جدول `audit_events` سجل مركزي إضافي؛ لا يستبدل `review_decisions` أو `document_events` أو `integration_attempts`. يراقب أحداث إنشاء/تعديل الحسابات والأقسام والخدمات والمنح والطلبات، وقرارات المراجعة، وأحداث الوثيقة والإصدار، والمرفقات والمواعيد والفحوصات والرسوم والإيصالات والتكاملات. تسجيل الدخول والخروج والفشل له أحداث مستقلة، وكذلك طلب/إتمام استعادة كلمة المرور وتصدير التقارير والتدقيق.

يحفظ معرف المنفذ من المصادقة/حدث الخادم، وقسمه وقت الحدث، ونوع ومعرف السجل، والتوقيت، وUUID للتتبع، ونتيجة تسجيل العملية. `success` يعني نجاح التغيير المسجل؛ حالة رفض/فشل التحقق تبقى في حقل تغير الحالة وفي تقرير المحاولات، ولا تعني نتيجة التدقيق نجاح التحقق الخارجي. تُحفظ حالات قبل/بعد للحقول الإدارية الآمنة فقط. أسماء الحقول الأخرى المتغيرة تُسجل دون قيمها. لا كلمات مرور أو تجزئاتها أو رموز استعادة/جلسة أو API أو رقم هوية أو تفاصيل طبية أو أجسام ردود التكامل أو IP.

تعديلات الإدارة والمعاملات التشغيلية تسجل التدقيق داخل المعاملة نفسها؛ rollback يلغي الحدث معها. لا توجد endpoints لتعديل التدقيق أو حذفه، ونموذجه يمنع ذلك. ارتباط المنفذ والقسم يمنع حذف التاريخ بعلاقة قاعدة البيانات. لا تُستعاد أحداث تاريخية افتراضيًا، ولا توجد مهمة حذف أو سياسة احتفاظ مدمرة. حساب قاعدة البيانات ذو الامتيازات الكاملة يستطيع تعديل الجداول مباشرة؛ إن تطلب النشر سجلًا غير قابل لتلاعب مسؤول قاعدة البيانات، يحتاج صلاحيات DB مقيدة/وجهة أرشفة مستقلة خارج نطاق الواجهة.

## تعريف التقارير والفلاتر

الفترات: اليوم، آخر 7 أيام شاملة اليوم، آخر 30 يومًا شاملة اليوم، بداية الشهر حتى الآن، وفترة مخصصة حتى 366 يومًا. تظهر المنطقة الزمنية الفعلية `config('app.timezone')`، ولا يُغيّر إعداد التطبيق. فلاتر القسم والموظف والخدمة وحالة الطلب تطبق في الخادم.

| المؤشر | المصدر والتعريف |
|---|---|
| الطلبات/حالاتها/خدماتها | صفوف الطلبات التي يقع `created_at` ضمن الفترة؛ كل طلب مرة واحدة |
| المفتوحة | من المجموعة السابقة، غير completed/rejected/cancelled |
| معدل الإكمال | المكتملة حاليًا من مجموعة الإنشاء / إجمالي المجموعة ×100 |
| معدل الرفض | المرفوضة حاليًا من مجموعة الإنشاء / إجمالي المجموعة ×100 |
| المكتملة في الفترة | الطلبات بحالة completed و`completed_at` ضمن الفترة، حتى إن أُنشئت سابقًا |
| متوسط المعالجة | متوسط الثواني بين created_at وcompleted_at للمكتملة في الفترة ذات تواريخ صحيحة؛ لا يمثل وقت العمل الفعلي |
| نشاط الموظف | قرارات `review_decisions.decided_at` في الفترة؛ عدد القرارات، COUNT DISTINCT للطلبات، وعدد action=approve |
| عبء الموظف | المفتوحة المنشأة في الفترة والمسندة حاليًا له |
| إكمال الموظف | completed_by وcompleted_at، ومتوسط الزمن من إنشاء الطلب إلى اكتماله |
| الوثائق الصادرة | وثائق مرتبطة بطلب منصة و`issued_recorded_at` في الفترة، حسب الحالة والخدمة؛ الوثائق القديمة دون تاريخ إصدار منصة موثوق مستبعدة |
| الرسوم | request_charges.created_at في الفترة بحسب حالتها، مستقلة عن تاريخ إنشاء الطلب |
| المدفوعات | إيصالات manual_payments.paid_at في الفترة ذات charge.status=paid وتطابق المبلغ والعملة؛ إيصال واحد لكل رسم بالقيد الموجود، لا تجمع محاولات التكامل كدفعات |
| مبالغ السداد | SUM للمبالغ المطابقة من قاعدة البيانات، منفصلة لكل عملة، مع الحفاظ على DECIMAL في MySQL؛ لا تشمل المستحق أو الاسترداد |
| المطابقة المالية | إيصالات الفترة غير المطابقة لشروط السداد أعلاه، تحتاج مراجعة ولا تدخل المجموع |
| التحقق | محاولات integration_attempts.started_at في الفترة، بحسب الحالة والنوع والمزود وorigin |
| نجاح التحقق المهيأ | verified ذات origin=configured_provider / جميع المحاولات المشمولة، بما فيها غير المتاحة والمحاكاة ×100 |
| الأقسام | مجموعات مستقلة للطلبات والقرارات والوثائق، مع عدد الموظفين/الأقسام النشطين حاليًا |

كل معدل ذي مقام صفر يظهر غير متاح. لا يُضاعف الطلب بانضمام مرفقات/إيصالات متعددة؛ تُستخدم تجميعات وEXISTS واستعلامات فرعية مستقلة. يمكن أن يعالج أكثر من موظف الطلب نفسه؛ لا تجمع أعداد الطلبات المميزة لكل موظف كإجمالي المنصة. لا يعد عدد العمليات حكمًا على جودة أداء الموظف.

**نطاق القسم الحالي:** الطلبات تتبع المسؤول الحالي assigned_to، والوثائق مُصدرها، والمدفوعات مسجلها، والقرارات والتكاملات منفذها. الارتباط بالقسم في التقارير هو ارتباط الموظف الحالي، وليس إعادة بناء تاريخ إداري غير مسجل. التدقيق وحده يثبت القسم وقت الحدث. الطلب غير المسند لا يظهر لتقارير قسم، لكنه داخل إجمالي المدير. حالات الحساب/القسم الحالية لا تعتبر مؤشرات زمنية.

**حدود البيانات:** لا SLA معتمد، لذا التأخير غير متاح. الإيصالات المحلية لا تحتوي مراحل بوابة دفع failed/pending/refunded؛ لا تُختلق هذه الحالات. لا عمليات إلغاء وثيقة رسمية أو إعادة إصدار خارجي مفترضة؛ حالات الوثائق وعلاقاتها القائمة تعرض كما هي. `simulation` يميز محول الاختبار، و`unknown` للسجلات القديمة/غير المهيأة، و`configured_provider` لمحول مهيأ معتمد في الإعدادات. لا يوجد مزود حقيقي مفعّل حاليًا. حالة المحاولة تاريخية؛ اعتماد الخدمة يعيد فحص الصلاحية الفعلية عبر المتطلب 11.

## التصدير والأداء

CSV فقط، دون إضافة مكتبات Excel/PDF. يحتوي العنوان والفترة وتاريخ الإنشاء والمنطقة والفلاتر، وتُحمى الخلايا البادئة بصيغ الجداول (`= + - @`، حتى بعد الفراغات والمحارف المتحكمة). لا معلومات هوية للمواطن أو ملاحظات طبية أو إيصالات تفصيلية داخل التقارير المجمعة. تصدير التدقيق للمدير فقط، بأعمدة آمنة دون قيم التغييرات.

التنزيل المباشر محمي في كل طلب و`no-store`، ولا يُحفظ ملف في public أو ينشأ رابط دائم. قوائم الموظفين والتدقيق والنشاط والأقسام بصفحات، وتصدير النشاط/الأقسام دفعات lazy(500)، والتدقيق chunkById(500) وحد أعلى للمعرف وقت الطلب لمنع نموه أثناء القراءة. لا يحتاج عامل Queue أو مهمة مجدولة جديدة. التصدير يقرأ بيانات التشغيل أثناء التنفيذ؛ ليس لقطة محاسبية مغلقة، وقد تتغير بيانات متزامنة أثناء الدفعات. الفهارس تغطي فترة الطلب/السداد/الإصدار والمنفذ والتوقيت والتصنيفات.
