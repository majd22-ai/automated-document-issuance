# فحص استهلاك الذكاء الاصطناعي والأداء

## نطاق الفحص والبيئة

فحص الكود المملوك للمشروع في `app` و`routes` و`config` و`resources` و`public/js` و`scripts` و`database` و`tests`، واعتماديات Composer وNPM. لم يتم طباعة ملف الأسرار أو محتويات حسابات المستخدمين. Laravel 12.65.0، PHP 8.2.12، Composer 2.10.2.

أظهر `php artisan about --only=environment,drivers,cache` أن الاتصال الحالي `mysql`، والتخزين المؤقت والجلسات والطوابير تستخدم `database`. قوالب Blade مجمعة، وإعدادات التطبيق والمسارات غير مجمعة في بيئة التطوير المحلية.

## النتائج

- لم توجد استدعاءات AI أو SDK مخصص لمزود AI أو إعداد نموذج أو Prompts أو سجل محادثات يرسل لنموذج في الكود المفحوص. البحث شمل أسماء المزودين، HTTP/Guzzle/cURL وطلبات JavaScript ونقاط API.
- `app` يحتوي نموذج المستخدم وأربعة متحكمات (منها المتحكم الأساسي) ووسيطي المصادقة ومزود التطبيق. لا توجد خدمات AI أو Jobs تطبيقية أو عمليات dispatch في كود التطبيق.
- Axios مثبت ومهيأ في `resources/js/bootstrap.js`، دون استدعاءات API تطبيقية فيه. وجود حزمة عميل HTTP لا يعني إرسال طلب مدفوع.
- `config/services.php` يحوي إعدادات Laravel للبريد وAWS/Slack، وليست نماذج AI. الخرائط والخطوط والصور الخارجية في الصفحات ليست استدعاءات نماذج توليدية.
- جداول cache وcache_locks وjobs وjob_batches وfailed_jobs موجودة في الترحيلات. لا توجد نتائج AI مناسبة لتخزينها مؤقتًا أو مهمة AI طويلة لنقلها إلى Queue حاليًا.
- بيانات صفحات الخدمات معرفة داخل المسارات؛ المعاينة التجريبية تستخدم التخزين المحلي في المتصفح. لم يتغير سلوكها.
- قائمة المدير كانت تجلب جميع أعمدة المستخدمين رغم أن القالب يحتاج ستة أعمدة فقط. إخفاء password في JSON داخل النموذج لا يمنع تحميله من قاعدة البيانات.

هذه نتائج فحص مصدر وإعدادات، وليست تقرير فوترة للمزود أو قياسًا لكل حركة الشبكة. لا توجد بيانات usage أو أسعار أو حساب مزود مرتبطة بالتطبيق يمكن منها حساب Tokens أو التكلفة. أرصدة أداة التطوير التي تعدل المشروع منفصلة عن تشغيل Laravel؛ تعديل استعلام داخل التطبيق لا يغير رصيد الأداة.

## التغيير المنفذ

`AdminUserController::index` يطلب فقط `id,name,username,email,role,is_active` بدل جميع الأعمدة. يحافظ على البحث بالاسم والبريد واسم المستخدم، الترتيب التنازلي والترقيم 15 حسابًا للصفحة، ومسارات التحديث والصلاحيات الحالية. لا يوجد تغيير مخطط أو حذف بيانات أو مكتبة جديدة أو Cache مشترك لبيانات المستخدمين.

## التحقق والقياس

أضيف اختبار `test_admin_listing_loads_only_display_fields_and_preserves_search_and_pagination` إلى الاختبارات القائمة. أنشأ حساب مدير و16 حسابًا مطابقًا للبحث في قاعدة معزولة، وفحص الصفحة الثانية ومجموع النتائج ووصلة الصفحة السابقة والأعمدة المحملة فعليًا، بما فيها عدم تحميل password وremember_token.

- قبل التغيير: فشل الاختبار وأظهر 12 عمودًا محملًا، تشمل password وremember_token وphone وحقول التواريخ.
- بعد التغيير: نجح الاختبار مع ستة أعمدة مطلوبة فقط. لم يتغير عدد استعلامات الترقيم؛ لا ندعي تقليله أو نسبة تسريع زمنية.
- نجحت مجموعة Laravel كاملة: 28 اختبارًا، 193 تحققًا، على SQLite المعزول.
- نجحت اختبارات المعاينة الأمامية الخمسة.
- تم تنسيق الملفين المعنيين بواسطة Pint، ثم إعادة الاختبارات والتحقق بعد التنسيق.

الأوامر:

```powershell
php artisan about --only=environment,drivers,cache
php vendor/bin/phpunit --do-not-cache-result
node --test tests/frontend/portal-demo.test.cjs
php vendor/bin/pint --test app/Http/Controllers/AdminUserController.php tests/Feature/UserAuthenticationTest.php
```

لا يوجد قياس قبل/بعد لـ Tokens لأن المشروع لا يحتوي مسار AI مرصودًا. لم تُختلق نسبة توفير، ولم تُرسل طلبات مدفوعة بغرض القياس.

## ما يحتاج معلومات إضافية

إذا كان تكامل AI في مشروع آخر أو فرع آخر، يلزم تحديد موقعه. وعند إضافة تكامل فعلي، يلزم تحديد المزود والموديل وعقد الاستجابة والمهام وسياسة الاحتفاظ بالبيانات قبل تعديل السياق أو النموذج أو التخزين المؤقت.

قياس ذلك التكامل يجب أن يفصل الطلب المنطقي عن المحاولات الفعلية، ويسجل request_id ومعرف المهمة والموديل ومدة الطلب وحالة الاستجابة وinput/output/cached tokens من usage الذي يرجعه المزود، دون نصوص المستندات أو المفاتيح أو بيانات المستخدمين. التكلفة تحسب من أسعار موثوقة بتاريخها مع تمييز Tokens المخزنة مؤقتًا إن كان المزود يفصل سعرها. تتم المقارنة على مهام متكافئة مع فحص جودة النتائج ومعدل نجاحها.

تحديد TTL ومفتاح Cache مرتبط بالمستخدم وصلاحياته وإصدار البيانات، ودعم idempotency لدى المزود وسياسة retry/backoff، قرارات تعتمد على تكامل غير موجود حاليًا؛ لم تُنشأ لها بنية غير مستخدمة. كما لم يُغيّر اختيار النماذج أو إعدادات Queue الافتراضية أو يجمع Cache لإنتاج صفحات مصادقة. تجميع المسارات والإعدادات يترك لعملية نشر الإنتاج؛ لم يفعّل في التطوير حتى لا يخفي تغييرات الإعدادات والمسارات.
