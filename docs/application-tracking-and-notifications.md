# تتبع الطلبات والإشعارات — المتطلب الوظيفي 10

## التنفيذ

المشروع Laravel 12.65 وPHP 8.2.12. أُعيد استخدام المصادقة والصلاحيات وعلاقات المواطن والطلبات والوثائق وسجلات المراجعة والإصدار والتسليم. يستخدم صندوق الإشعارات Laravel Notifications وعلاقة Notifiable الموجودة؛ لا يوجد جدول موازٍ لتاريخ الحالات.

- قائمة طلبات المواطن وبحث الموظف المخوّل ضمن خدماته، مع تصفية المرجع الكامل والخدمة والحالة وتواريخ التقديم والتحديث، وتقسيم النتائج إلى صفحات.
- تفاصيل المرحلة الحالية والخطوة التالية والقرار العلني الأخير والإصدار والتسليم. الخط الزمني يجمع السجلات الفعلية فقط، مع صفحات، دون اختلاق تواريخ قديمة أو عرض الملاحظات الداخلية.
- صندوق إشعارات خاص بالمواطن، وعدّاد غير المقروء، والتصفية والقراءة الفردية والجماعية. فتح الرابط يعيد فحص ملكية الطلب والوثيقة والصلاحية على الخادم؛ لا يقبل روابط خارجية من المحتوى.
- إشعارات من منطق تقديم الطلب والمراجعة والاعتماد والإصدار والتسليم والإكمال والرسوم المستحقة ومتطلب الموعد. مفتاح فريد لكل حدث يمنع تكرار الإرسال عند إعادة تنفيذ الحدث، ويسمح بإشعار جديد لقرار جديد حقيقي.
- تنبيه انتهاء الوثائق بسياسة قابلة للضبط، مع أقرب عتبة مستحقة فقط عند تفويت تشغيل سابق، واستبعاد الحسابات المعطلة والوثائق الملغاة والمستبدلة والوثائق دون انتهاء صالح. لا تجديد تلقائي ولا مدد رسمية مفترضة.
- الإشعار الداخلي محفوظ داخل معاملة العمل. البريد الخارجي بعد نجاح المعاملة، وعطل الطابور لا يلغي التغيير المحفوظ. الرسالة البريدية عامة وتتطلب تسجيل الدخول لرؤية التفاصيل.

## التشغيل

طُبّق الترحيل الإضافي على قاعدة MySQL المحلية دون حذف بيانات أو استعمال `migrate:fresh`. لم تنشأ إشعارات تاريخية وهمية. تهيئة البريد الحالية `log` والإرسال البريدي الاختياري معطل؛ لم يُرسل بريد خارجي في التحقق.

حدد أيام التنبيه وفق سياسة المشروع في `.env`، مثل قائمة أعداد صحيحة تفصلها فواصل في `DOCUMENT_EXPIRY_ALERT_DAYS`؛ القيمة الافتراضية فارغة فلا تفترض مهلة. `DOCUMENT_EXPIRY_ALERT_STATUSES=active`، و`DOCUMENT_EXPIRED_ALERT_POLICY=skip` أو `once` لتنبيه واحد بعد الانتهاء.

```powershell
php artisan documents:notify-expiry
php artisan notifications:dispatch-mail
php artisan schedule:list
php artisan schedule:work
php artisan queue:work --queue=notifications,default --tries=1
```

في التشغيل المستمر اضبط Windows Task Scheduler لتشغيل `php artisan schedule:run` كل دقيقة من مجلد المشروع، وشغّل عامل الطابور كخدمة مناسبة. لم تُنشأ مهمة نظام أو خدمة عامل دائمة تلقائيًا. موعد تنبيه الوثائق 08:00 بحسب منطقة التطبيق الحالية UTC (11:00 بتوقيت الرياض)، وليس بحسب توقيت الجهاز؛ إرسال البريد المعلّق يفحص كل دقيقة.

لتفعيل البريد يلزم إعداد مزود حقيقي مدعوم وإعدادات `MAIL_*` ومرسل صالح، ثم `CITIZEN_NOTIFICATION_MAIL_ENABLED=true` وطابور غير متزامن مثل `QUEUE_CONNECTION=database`. يشترط بريد مستخدم موثّق لم يتغير منذ إنشاء الإشعار. لا تحفظ المفاتيح في Git. بعد تغيير إعدادات مخبأة نفذ `php artisan config:clear` وأعد تشغيل العامل.

فشل البريد لا يمس الصندوق الداخلي. إعادة محاولة الفشل صريحة ومحدودة بثلاث محاولات افتراضيًا:

```powershell
php artisan notifications:dispatch-mail --retry=UUID
```

تُستعاد مهام `queued` العالقة بعد 15 دقيقة، ويمنع حجز قاعدة البيانات عاملين من إرسال الرسالة نفسها بالتوازي. حالة `sending` غير المؤكدة بعد انهيار عامل تحتاج مراجعة تشغيلية ولا يعاد إرسالها آليًا. لا يمكن ضمان التسليم الخارجي مرة واحدة تمامًا إذا قبل المزود الرسالة ثم انقطع الرد. لا SMS أو تكامل خارجي مفترض، ولا كشف لأسباب الرفض أو بيانات الوثيقة الحساسة داخل البريد.

## التحقق

```powershell
php vendor/bin/phpunit --do-not-cache-result
node --test tests/frontend/portal-demo.test.cjs
php artisan view:cache
```

لاختبار MySQL اضبط متغيرات العملية على قاعدة معزولة تنتهي بـ `_testing`، ثم نفذ مجموعة PHPUnit واختبارات `tests/Integration` بشكل متتابع. لا تشغّل مجموعتي قواعد البيانات بالتوازي لأن اختبارات التخزين تستخدم مسارات وهمية مشتركة. اختبارات البريد تستعمل Mail::fake أو محاكاة الفشل، ولا تختبر التسليم إلى مزود حقيقي. الواجهات اختُبرت عبر HTTP وتجميع Blade دون معاينة بصرية بالمتصفح.

النتائج الفعلية: المجموعة الكاملة على SQLite **186 اختبارًا و1347 تأكيدًا**، وعلى MySQL **186 اختبارًا و1347 تأكيدًا**؛ اختبارات التزامن **12 اختبارًا و69 تأكيدًا**، منها ثلاثة خاصة بتنبيهات الانتهاء وحجز البريد وفشل الإرسال إلى الطابور بعد الحفظ. نجحت اختبارات JavaScript الخمسة وتجميع Blade وفحص Pint و`git diff --check`. أكدت المراجعة المستقلة حماية الروابط والتزامن واستمرار الإشعار الداخلي عند تعطل الطابور دون عائق ملموس متبقٍ ضمن النطاق.

بعد الترحيل بقيت قاعدة التشغيل: مستخدم واحد، سبع خدمات، صفر طلبات ووثائق وإشعارات. انتهت قاعدة الاختبار دون مستخدمين أو طلبات أو وثائق أو إشعارات متروكة. نجحت أوامر التنبيه والبريد المعلق بإنتاج صفر إشعارات وفق الإعدادات الحالية، وعرضت الجدولة المهمتين بنجاح.
